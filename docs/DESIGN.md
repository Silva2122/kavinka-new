Референсы мягкие (арки, пилюли, вензеля) — это женская аудитория. У нас рыболовная база, аудитория мужская. **Важная поправка в процессе:** первая версия этого документа советовала выкинуть скругления и пилюли совсем — Босс потом явно попросил вернуть мягкость (скруглённые кнопки, пилюля координат), совместив её с камуфляжем и брутальными деталями. Итоговая формула — не «брутализм», а **тёплая природная палитра с камуфляжем как единственным жёстким акцентом**, подробнее в разделе 5.

Референс заглушки от Босса: **`https://silva2122.github.io/kavinka/`** — его собственный черновик. Оттуда взят приём стеклянной пилюли для координат (`blur`, полупрозрачный фон, точка-разделитель) и общий язык «стекла» для кнопок.

## 2. Камуфляж — фирменный приём

Файл: `public/photo/camo.jpg`.

На прошлом сайте Босс наложил камуфляж на прозрачную кнопку — заказчику очень понравилось. В утверждённом hero это развито в две парные системы:

- **На тёмном фоне** (hero-панель) — класс `.glass-btn`: полупрозрачное стекло (`backdrop-filter: blur`), камуфляж отдельным слоем на **34% opacity** в покое (было 62% — резалось в текст, пришлось приглушать), кремовая вуаль поверх усиливает читаемость, при hover камуфляж уплотняется до 48%.
- **На светлом фоне** (кнопка «Подробнее» в «О базе») — класс `.camo-btn`: камуфляж плотнее, тёмная вуаль `rgba(35,35,24,.5)` поверх для контраста с кремом.

Более ранняя идея — заливать камуфляжем весь фон панели или делать «рваный бумажный переход» между секциями зелёного цвета — **опробована и отклонена**, см. раздел 6.

Правило, подтверждённое на практике: камуфляж — **акцент на маленьких объектах** (кнопка), а не на больших площадях. На всей панели он либо невидим (слишком блёкло), либо рябит.

## 3. Палитра — актуальная, из `design/page.html`

⚠️ Отличается от значений в `app/globals.css` — при переносе в Next.js нужно **заменить токены**, не сливать со старыми.

```css
--cream:      #F0EFE4;  /* основной светлый фон секций */
--cream-warm: #E7E2CE;  /* фон бегущей строки — чуть темнее cream */
--bog:        #242B1B;  /* тёмные секции: hero-панель, "Виды рыб" */
--sage:       #B7C299;  /* второй цвет двухцветных заголовков, светлые акценты на тёмном */
--olive:      #7C8C57;  /* акцент на светлом: иконки, крупные цифры, точки */
--ink:        #232318;  /* текст на светлом фоне, тёплый почти-чёрный */
--muted:      #6E6D5E;  /* второстепенный текст */
```

Старые токены `sand`, `moss`, `bark`, `stone`, `olive-light` из первой версии документа и `app/globals.css` **не используются** в утверждённом hero — считать их устаревшими черновиками, не смешивать.

**Emerald по-прежнему отменён** — старый акцент прототипа `#059669` отношения к текущей палитре не имеет.

## 4. Типографика — два шрифта, не три

```css
--disp: 'Cormorant Garamond', Georgia, serif;   /* заголовки */
--body: 'Manrope', system-ui, sans-serif;        /* всё остальное, включая "технический" слой */
```

**JetBrains Mono отменён.** Первая версия дизайна планировала третий, моноширинный шрифт для координат/цен/дат. На практике это резало глаз — «слишком много разных шрифтов». «Технический» вид (координаты, цена, кнопки) теперь даёт не отдельная гарнитура, а **Manrope капсом с трекингом**:

```css
--meta-size: 14px;
--meta-tracking: .12em;
--base-size: 18px;  /* обычный текст абзацев */
```

Playfair Display тоже заменён на **Cormorant Garamond** — Playfair показался слишком предсказуемым («Inter среди антикв», буквально предупреждение из кукбука Anthropic про AI-generated дизайн). Cormorant даёт больше тепла, ближе к референсам Босса.

### Заголовок-слоган: два ряда со сдвигом

Фирменный приём hero, скопирован из заглушки Босса (`h1 strong{transform:translateX(...)}` в её CSS) и адаптирован под кириллицу:

```html
<h1 class="slogan-h1">
  <span class="ln">Пароль в мир</span>
  <span class="ln">дикой природы</span>
</h1>
```

Вторая строка сдвинута вправо через `transform: translateX(.85em)` — **в `em`, не в `vw`**. Это специально: при отдельном масштабировании шрифта и сдвига по ширине экрана на средних разрешениях (1024–1440px) слово банально обрезалось за край панели. Сдвиг в `em` растёт вместе со шрифтом и никогда не рассинхронизируется. Если будешь трогать эту вёрстку — не возвращай `vw`-сдвиг, это наступит на старые грабли.

Размер самого заголовка задан в два яруса под ширину экрана (не единым `clamp`, а с точкой перелома на `1100px`) — тоже защита от обрезания на средних ширинах. Детали — в самом `page.html`, класс `.slogan-h1 .ln` и медиа-запрос `min-width:1100px`.

### Двухцветный заголовок

```
О БАЗЕ       ← "БАЗЕ" цветом --sage
```

Приём из референсов, используется во всех H2.

## 5. Принципы вёрстки — обновлено по факту

1. **Скругления есть.** Пилюли у кнопок (`border-radius:100px`), у карточек — скромный радиус `6-8px`. Первая версия документа запрещала скругления полностью — это было ошибкой, Босс прямо попросил вернуть мягкость.
2. **Тени — по минимуму**, только мягкие (у кнопок `box-shadow` с большим blur), никаких резких.
3. **Один осознанный крупный элемент на экран** — не размазывать эффекты. В hero это заголовок-слоган; в остальных секциях крупный акцент ещё предстоит найти (см. раздел 7).
4. **Секции чередуются светлое/тёмное.** Актуальный порядок на главной: hero (тёмная, фото) → «Быстрые факты» (светлая, `--cream`) → «О базе» (тёмная, видео) → «Виды рыб» (светлая, `--cream`) → CTA (тёмная, видео) → футер (тёмная, `--bog`). «Виды рыб» специально сделана светлой (а не тёмной, как было в первой отклонённой версии) — иначе после «О базе» шли бы два тёмных видео-блока подряд и ритм ломался. Ритм светлое/тёмное из референса «Золотое», конкретное чередование — по факту того, что получилось на главной.
5. **Реальные факты вместо декора.** Если что-то похоже на украшение (нумерация, схема, диаграмма) — это должно быть основано на настоящих данных проекта (координаты, сезоны, реальная география), а не выдумано для красоты. Требование сформулировано явно после того, как Boss отверг фиктивный «календарь сезона» на этапе вайрфреймов.
6. **Единая шкала размеров.** Не подбирать «почти одинаковые» значения на глаз — по факту резало глаз как хаос, пришлось делать отдельный проход по всей главной, чтобы свести. `--meta-size` — служебные элементы (пилюля, кнопки, цена, киккер). Полная шкала для карточек/сеток/заголовочных блоков — раздел 10, переменные `--size-h3`/`--size-h3-sm`/`--size-copy`/`--size-small`/`--grid-max`/`--head-max`. Заводя новую секцию — брать размеры оттуда, не придумывать новые числа.
7. **Мобильная адаптация — отдельная, осознанно отложенная задача.** По решению Босса сначала доводим десктоп до сдачи заказчику, потом возвращаемся к мобильной вёрстке. Черновые mobile-правила в hero есть (`@media max-width:860px`), но не финальны и не проверялись так же тщательно, как десктоп.

## 6. Что уже пробовали и отклонили — не предлагать снова

- **Рваный бумажный переход между секциями** (SVG с неровным краем + процедурное зерно через `feTurbulence`, покрашенный то в собственный «бумажный» зелёный, то в цвет соседней секции). Технически сделано аккуратно и проверено на нескольких вариантах цвета, но Босс решил вообще убрать любые переходы между секциями — «не нужны ни в каком виде». Секции теперь стыкуются напрямую, без декоративной границы.
- **Заголовок «Пароль в мир дикой природы» в 4 строки** с сдвигом каждой строки вразнобой — Босс попросил вернуть к 2 строкам («Пароль в мир» / «дикой природы»), как в референсной заглушке.
- **Огромное имя «КАВИНКА» на всю панель hero** (было в ранних версиях v1–v5) — отклонено, имя переехало в маленький вордмарк в шапке, а место в hero занял слоган.
- **Кикер и лид-абзац как отдельные придуманные тексты** — оказалось, что часть текста в ранних версиях hero была сочинена, не взята из `STRUCTURE.md`. Исправлено: весь текст в утверждённом hero дословно из структуры или банка текста сайта.
- **Секция «О базе» в виде фото слева / текст справа**, фото в рамке 4:5 — забраковано как «дефолтно, шаблонно». Пробовали также вариант с фото на вылет к краю + карточками-фактами + мини-диаграммой слияния рек — **тоже забраковано** («отвратительно»), без уточнения деталей. Требуется полностью новый заход, не косметика.
- **Секция «Виды рыб»** (тёмная, сетка из 6 карточек с видео) — тоже названа «отвратительной» в той же реплике, без отдельных деталей. Тоже требует полного редизайна.

## 9. Утверждённые компоненты «Быстрые факты» и «О базе» (переиспользовать как есть)

«О базе» прошла путь в несколько итераций за один заход — от словесных концепций (все отвергнуты как «слишком сложно» и «не идёт от референсов», см. `DECISIONS.md` №16) к конкретному приёму из присланного референса «Италия» (стемпы-модули программы тренинга). Рабочий процесс, который сработал и стоит повторить для «Виды рыб»: показывать 2-3 конкретных приёма **с привязкой к конкретной картинке из `ref/`**, а не абстрактные идеи, и делать HTML-мокап с реальным скриншотом на каждой правке, а не описывать словами.

**Быстрые факты** (между hero и «О базе», лёгкая пауза-выдох):
- Секция на `--cream`, без фото и тёмных панелей — короткий кикер + двухцветный H2 + лид по центру, затем 4 карточки в ряд.
- Карточки — только тонкая обводка `rgba(35,35,24,.12)`, скругление 10px, без заливки; при hover обводка становится `--olive`. Внутри — круглая иконка-обводка 60px с line-art SVG (`--olive`), заголовок капсом, короткая подпись.
- Текст карточек — дословно из `STRUCTURE.md` §3.2 (Проживание/Рыбалка/Река Тауй/Гиды), не сочинять новые пункты.

**О базе** (полноэкранная видео-секция сразу после):
- Секция без вертикальных отступов (`padding:0 46px`) — фон стыкуется с hero сверху и с «Виды рыб» снизу напрямую, без зазора. Высота — `min-height:82svh`, ощутимо крупный блок.
- Фон на всю ширину экрана (`.about__stage`, bleed за счёт отрицательных полей у `.about` + `width:calc(100% + 92px)` у стейджа) — **сейчас видео** `lake-ripples.mp4` (было фото `base-from-water.jpg`, Босс попросил заменить на «оживлённую» версию той же сцены — по факту тот же кадр, сгенерированный в видео с рябью на воде). Разметка держит оба варианта: `.about__stage img,.about__stage video{...}` — общее правило, менять источник — просто заменить тег. Диагональный тёмный градиент сильнее слева (где текст) и мягче справа (где карточки на своём тёмном фоне).
- Текст (H2 сплошным `--cream`, без двухцветности — на фото зелёное слово сливалось с деревьями, поэтому здесь заголовок одноцветный, в отличие от карточек «Быстрых фактов») и кнопка `.glass-btn` (та же, что в hero) — в левом верхнем углу.
- Факты — «пропуска» (`.pass`): тёмные бог-зелёные плашки, друг под другом у правого края, зазор 6px, ширина одинаковая. Заголовок и подпись внутри карточки не центрированы и не растянуты — идут единым блоком сверху.
- Перфорация у пропусков — **настоящий CSS-вырез через `mask-image`/`mask-composite:intersect`** (два `radial-gradient`, один сверху, один снизу, пересечение вырезает волну по обеим кромкам), а не подделка цветом фона. Это принципиально: цветовая подделка ломается, если карточка на фото или повёрнута под углом — настоящая маска работает всегда, потому что реально прозрачна. Если понадобится похожий перфорированный край где-то ещё — переиспользовать этот же приём, не изобретать заново.
- Карточки **не крутить и не разбрасывать в стороны** (был промежуточный вариант с `rotate()` и разной высотой — отклонён явно: «почему поехали эти дырки», «как-то криво»). Ровный вертикальный стек — единственное утверждённое положение.

## 10. Утверждённые компоненты «Виды рыб», CTA, футер, хедер, анимация — вся остальная главная

### Виды рыб — список слева, видео справа (не сетка карточек)

Финальная форма радикально не похожа на обе отклонённые версии (см. `DECISIONS.md` №15, №17). Приём выбран из референса «Дагестан» (карточка-билет), но в процессе Босс сам предложил заменить сетку на интерактивный список:

- Слева — `.fish-list`: вертикальный список из 6 строк (`.fish-list__item`, это `<button>`), у каждой номер («01»…«06»), название рыбы, сезон, стрелка `→`, которая появляется при наведении/активности. Разделены тонкими линиями (`border-top`, только `rgba(35,35,24,.14)`), без заливки.
- Справа — `.fish-stage`: одна сцена с 6 видео, наложенными друг на друга (`position:absolute`), кроссфейд по `opacity` между `.is-active` — **тот же приём**, что в галерее трофеев hero (`.gallery__slide.is-active`), просто по наведению на список, а не по таймеру.
- Наведение (`mouseenter`) и клик на строку списка переключают активные класс у строки и у соответствующего видео (JS в конце `page.html`, ищет по `data-index`).
- **aspect-ratio сцены — `16/9`, не `4/3` и не `3/2`.** Пробовали оба — рыба (снятая широким кадром) обрезалась по бокам при не-16:9 контейнере, потому что источник видео буквально 16:9 (1920×1080) и `object-fit:cover` обрезает лишнее по короткой стороне. Если появятся видео другого нативного соотношения — держать `aspect-ratio` сцены равным соотношению исходника, иначе обрежет.
- Секция **светлая** (`--cream`), не тёмная — см. раздел 5, пункт 4 (ритм чередования).
- Видео — **новые**, сгенерированные отдельно от старых (`public/video/fish-*-swim.mp4`, «плывущая» рыба, не то же самое, что исходные `fish-*.mp4`, из которых просто вырезали стоп-кадр). Есть повторяющаяся путаница между «видео для стоп-кадра» и «видео для проигрывания» — если понадобится ещё раз, `fish-*-swim.mp4` это те, что реально показываются.
- **Пробовали и отклонили: тонировать видео в болотный цвет** (`mix-blend-mode:color` поверх, чтобы вода была ближе к фирменной палитре) — Босс попросил вернуть как было сразу же, естественный цвет воды. Не предлагать снова без явного запроса.
- **Пробовали и отклонили: горизонтальная карусель с 3×2 карточками-билетами и стрелками влево/вправо** (аналог стрелок в галерее hero) — сделано и работало технически, но Босс передумал на середине объяснения и попросил вернуть 3 карточки в ряд компактнее. Затем эта версия тоже была заменена на список+сцену. Если предложите карусель для рыб снова — уже пробовали, не понравилось не по техническим причинам, а по вкусу.

### CTA — сплошной блок с видео

Последняя секция главной, `STRUCTURE.md` §3.5. Тот же приём, что «О базе»: видео на всю ширину (`cta-trout.mp4`), тёмный градиент, контент поверх. Отличие — контент по центру в одну колонку (`max-width:var(--head-max)`), без второй колонки с карточками, потому что по структуре это просто «H2 + текст + кнопка», не более. Заголовок — дословно из структуры, **одноцветный** `--cream` (не двухцветный) — по той же причине, что и в «О базе»: на видео двухцветность не читается.

### Футер

Тёмный (`--bog`), три колонки строго по `STRUCTURE.md` §2 (Контакты / Навигация — 4 пункта / О компании), низ — копирайт + дисклеймер. Текст колонки «О компании» — дословная цитата из структуры. Телефон — тот же плейсхолдер `+7 914 000-00-00`, что и everywhere on сайте (см. открытые вопросы к заказчику).

### Закреплённый хедер

`.site-header`, `position:fixed`, скрыт наверху (`transform:translateY(-100%);opacity:0`), появляется при скролле — JS-порог `scrollY > innerHeight * 0.6` (примерно после того, как hero прокручен). Фон — **болотный `--bog`, не камуфляж**: камуфляж на большую сплошную плашку уже пробовали и отклонили на этапе hero (раздел 2, раздел 6) — то же самое правило применили здесь не спрашивая, вместо камуфляжа предложили сразу болотный цвет, и это подошло. Компактнее, чем секция-хедер в hero (меньше паддинги, меньше кнопка) — по прямой правке Босса «хедер огромный, кнопку тоже уменьши».

### Анимация появления при скролле

Общий класс `.reveal` (см. `:root` и правило `.reveal`/`.reveal.is-visible` в начале `<style>`) + один `IntersectionObserver` в конце `page.html`, применён почти ко всем текстовым/медиа-блокам на странице. Стагтер внутри группы (карточки фактов, пропуска, строки списка рыб) — через инлайновую CSS-переменную `style="--i:N"`, которая двигает `transition-delay`. Уважает `prefers-reduced-motion`.

**Техническая ловушка, если будешь трогать `.fish-list__item`:** у него `all:unset` (нужно было сбросить стили `<button>`) — это стирает `opacity`/`transform`, которые ставит `.reveal`, если `.reveal` определён раньше в каскаде (а он определён в начале файла, до всех секционных стилей). Решение — отдельное правило с более высокой специфичностью **после** `all:unset`: `.fish-list__item.reveal{...}`. Если где-то ещё понадобится `.reveal` на элементе с `all:unset` или другим сбросом стилей — тот же приём, не полагаться на порядок в файле.

### Единая сетка и шкала шрифтов — переменные в `:root`

Отдельный проход по всей главной, чтобы секции не отличались друг от друга «на глаз» (было: где-то шире контейнер, где-то у́же; где-то заголовок карточки 23px, где-то 31px, где-то 38px — без системы). Введены переменные:

```css
--grid-max: 1440px;   /* ширина контентной сетки — .facts__grid, .fish-explorer, .footer__top, .about__content */
--head-max: 620px;    /* ширина заголовочного блока (эйбрау+H2+лид) — .facts__head, .fish-section__head, .cta-section__content */
--size-h3: 28px;      /* заголовки в широких карточках/строках — .pass h3, .fish-list__name */
--size-h3-sm: 22px;   /* заголовки в узких карточках — .fact-item h3 (4 в ряд, у́же, чем .pass) */
--size-copy: 14.5px;  /* второстепенный текст внутри карточек и в футере — .pass p, .fact-item p, .footer__col */
--size-small: 12.5px; /* третичные подписи — сезон/номер в списке рыб, копирайт в футере */
```

Заводя новую секцию (в том числе на второй странице) — брать размеры и ширины отсюда, не подбирать новые числа на глаз. Если нужен принципиально другой масштаб — обсудить с Боссом и завести новую именованную переменную, а не одноразовое число внутри правила.

**Техническая ловушка при выравнивании полноэкранных видео-секций (`.about`, `.cta-section`):** если внутренний контент — flex-контейнер с `justify-content:space-between` (как `.about__content`, текст + карточки по разные стороны), и нужно ограничить его ширину `max-width` + `margin:auto` для центрирования на широких экранах — учитывай, что контент обычно живёт внутри уже «выбеленного» (bleed) стейджа шириной `calc(100% + 2×паддинг)`. Чтобы после центрирования плюс внутренний паддинг общий отступ от края совпадал с остальными секциями (46px + автоцентрирование = те же ~80px на 1600px экране), `max-width` должен быть `var(--grid-max) + величина bleed`, а не просто `var(--grid-max)` — иначе получится двойной отступ. Разобрались на практике на «О базе», см. историю в `DECISIONS.md` №17.
